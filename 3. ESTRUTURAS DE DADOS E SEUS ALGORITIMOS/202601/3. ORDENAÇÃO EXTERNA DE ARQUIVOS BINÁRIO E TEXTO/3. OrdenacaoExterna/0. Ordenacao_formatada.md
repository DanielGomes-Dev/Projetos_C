## 1. Ordenação Externa de Arquivos

### Motivação e Métodos Iniciais

* **Motivação:** Busca binária exige que arquivo esteja ordenado.
* **Como ordená-lo?**
* **Métodos de ordenação de arquivos?**
* **Ordenação em memória: Como funciona?**
* Dados são lidos para um array de memória;
* Usar algum algoritmo de ordenação já existente na literatura; e
* Gravar novo arquivo com os dados ordenados.



### Alguns algoritmos da literatura

#### SelectionSort

```c
void ord_sel_sort(int *vet, int n){
 int i;
 for(i = 0; i < n; i++){
 int j, menor = i;
 for(j = i + 1; j < n; j++)
 if(vet[j] < vet[menor])
 menor = j;
 if(menor != i){
 int temp = vet[i];
 vet[i] = vet[menor];
 vet[menor] = temp;
 }
 }
}

```

* **Complexidade:** O tempo gasto em `ord_sel_sort` é proporcional ao número de comparações:
* Primeira passada: $(n – 1)$
* Segunda passada: $(n – 2)$
* Terceira passada: $(n – 3)$
* ...
* Última passada: $1$


* A soma desses termos supracitados é proporcional a $n^2$. Portanto, sua complexidade é $O(n^2)$.

#### QuickSort

* Algoritmo mais rápido que existe: geralmente, $O(n \log n)$.
* Algoritmo recursivo.
* `ord_sel_sort` coloca o menor elemento na primeira posição $\rightarrow$ QuickSort faz isso com um elemento arbitrário chamado **pivô**.

**Ideia do QuickSort:**

* Suponha que o pivô deva ocupar a posição $i$ do vetor.
* Suponha também que $v[0] ... v[i – 1]$ são menores que o pivô, e $v[i + 1] ... v[n – 1]$ sejam maiores que o pivô.
* Posiciona-se o pivô em $v[i]$.
* Ordenam-se os vetores $v[0] ... v[i – 1]$ e $v[i + 1] ... v[n – 1]$ recursivamente. Quando os vetores tiverem zero elementos, a ordenação está concluída.
* Para a maioria das entradas, QuickSort é $O(n \log n)$.
* **Entradas que fazem a complexidade desse algoritmo ser $O(n^2)$?**

**Funcionamento da Versão Usada:**

* Pivô igual à $v[0] = x$.
* Início do vetor: Comparam-se $v[1], v[2],…$ até $v[a] > x$.
* Final do vetor: comparam-se os elementos $v[n - 1], v[n – 2], …$ até encontrar $v[b] \leq x$.
* Troca-se $v[a]$ e $v[b]$ e as buscas continuam com $v[a + 1]$ (do início do vetor) e $v[b – 1]$ (do final do vetor).
* Em algum momento, as buscas terminam porque os índices se cruzam, isto é, $a > b$.
* Nesse momento, a posição correta de $x$ está definida e os valores de $v[0]$ e $v[b]$ são trocados.
* O vetor $v[0] ... v[b – 1]$ possui somente elementos menores ou iguais a $x$ e o vetor $v[b + 1] ... v[n – 1]$ possui somente elementos maiores ou iguais a $x$.
* Ordenam-se recursivamente os vetores $v[0] ... v[b – 1]$ e $v[b + 1] ... v[n – 1]$.

#### Algoritmo QuickSort (qs)

```c
void qs(int *v, int n){
 if(n <= 1) return;
 int x = v[0], a = 1, b = n - 1;
 do{
 while((a < n) && (v[a] <= x)) a++;
 while(v[b] > x) b--;
 if(a < b){
 int temp = v[a];
 v[a++] = v[b];
 v[b--] = temp;
 }
 }while(a <= b);
 v[0] = v[b];
 v[b] = x;
 qs(v, b);
 qs(&v[b + 1], n – b - 1);
}

```

### Ordenação em Arquivos Binários

* **Se o arquivo cabe todo em memória principal?** Usar ordenação em memória mesmo. Se quiser economizar memória: Ordenar arquivo binário.
* **Se o arquivo não cabe todo?** Ordenar arquivo binário.
* **Por que só pode ser feito em arquivos binários?** Necessário usar `fseek` para se deslocar.

#### SelectionSort em arquivo binário

```c
void ord_sel_sort_Bin(FILE *fp){
 int i, j, r, s, elem_menor, menor, elem, aux;
 i = ftell(fp);
 r = fread(&elem_menor, sizeof(int), 1, fp);
 while(r == 1){
 menor = i;
 aux = elem_menor;
 j = ftell(fp);
 s = fread(&elem, sizeof(int), 1, fp);
 while(s == 1){
 if(elem < elem_menor){
 menor = j;
 elem_menor = elem;
 }
 j = ftell(fp);
 s = fread(&elem, sizeof(int), 1, fp);
 }
 if(menor != i){
 printf("Trocar %d(%d) por %d(%d)\n", aux, i, elem_menor, menor);
 fseek(fp, menor, SEEK_SET);
 fwrite(&aux, sizeof(int), 1, fp);
 fseek(fp, i, SEEK_SET);
 fwrite(&elem_menor, sizeof(int), 1, fp);
 }
 else{
 fseek(fp, (i + sizeof(int)), SEEK_SET);
 }
 i = ftell(fp);
 r = fread(&elem_menor, sizeof(int), 1, fp);
 }
}

```

## 2. Geração de Partições Classificadas

### Introdução e Conceitos

* **Material:** Baseado nos slides da Professora Vanessa Braganholo.
* **Ordenação de Arquivos Grandes:**
* Para **arquivos binários**, é possível implementar o algoritmo de ordenação diretamente em disco.
* Para **arquivos texto** (acesso sequencial), o acesso não pode ser feito em posições aleatórias. Para ler o 10º item, é necessário ler os 9 anteriores. Portanto, não é possível implementar a ordenação direto em disco.



### Tipos de Classificação

* **Classificação Interna:** Utilização exclusiva de memória principal (todo o conteúdo do arquivo cabe nela).
* **Classificação Externa:** Utilização de memória secundária (há mais conteúdo do que o possível manter na memória principal).
* **Atenção:** Nesta disciplina, o termo "classificação" é usado como sinônimo de "ordenação".
* O parâmetro fundamental é o **número de operações de entrada e saída**, que deve ser o menor possível.



### Modelo da Classificação Externa

A classificação externa divide os arquivos em pequenas frações que são ordenadas e intercaladas em duas etapas:

1. **Geração de partições classificadas.**
2. **Intercalação.**

---

### Métodos de Geração de Partições

Considera-se que a memória principal tenha capacidade para armazenar **M** registros.

#### 1. Classificação Interna

Consiste na leitura de $M$ registros para a memória, classificação por qualquer processo interno (Bolha, SelectionSort, QuickSort, HeapSort) e gravação em uma partição.

* Todas as partições contêm $M$ registros (exceto a última).

**Exemplo de Classificação Interna:**

* **Chaves:** 29, 14, 76, 75, 59, 6, 7, 74, 48, 46, 10, 18...
* **Memória (M):** 6 registros.
* **Processo:** Lê [29, 14, 76, 75, 59, 6] $\rightarrow$ Ordena $\rightarrow$ Grava Partição 1: [6, 14, 29, 59, 75, 76].

**Implementação (Trecho):**

```c
int classInterna(char *nome, char *parte){
    // ... (Leitura de n registros)
    qsort(vet, i, sizeof(int), compara);
    // ... (Gravação em arquivo parteN.txt)
}

```

#### 2. Seleção com Substituição

Aproveita a possível classificação parcial do arquivo de entrada.

* **Algoritmo:**
1. Ler $M$ registros para a memória.
2. Selecionar o registro $r$ com a **menor chave**.
3. Gravar $r$ na partição de saída.
4. Substituir $r$ pelo próximo registro do arquivo de entrada.
5. Se a nova chave for **menor** que a recém-gravada, o registro é **congelado** (ignorado nesta partição).
6. Repetir até que todos os registros em memória estejam congelados.
7. Iniciar nova partição e descongelar todos.


* **Eficiência:** Em média, o tamanho das partições geradas é de $2 \times M$.

---

## 3. Seleção Natural e Comparação

### Seleção Natural

**Desvantagem da seleção com substituição:** No final da partição, grande parte do espaço em memória principal está ocupado com registros congelados.

Na **seleção natural**, reserva-se um espaço de memória secundária (o **reservatório**) para abrigar os registros congelados num processo de substituição.

* A formação de uma partição se encerra quando o reservatório estiver cheio ou quando terminarem os registros de entrada.
* Para memória comportando $M$ registros e reservatório comportando $n$ registros:
* Se $M = n$, o comprimento médio das partições é de $M \times e$ (onde $e \approx 2,718$).



**Algoritmo:**

1. Ler $M$ registros do arquivo para a memória.
2. Selecionar, no array em memória, o registro $r$ com menor chave.
3. Gravar o registro $r$ na partição de saída.
4. Substituir $r$ pelo próximo registro do arquivo de entrada.
5. Caso a chave deste último seja **menor** do que a chave recém-gravada, gravá-lo no **reservatório** e substituir $r$ pelo próximo registro da entrada.
6. Caso ainda exista espaço livre no reservatório, voltar ao passo 2.
7. Caso contrário:
* Fechar a partição de saída.
* Copiar os registros do reservatório para o array em memória.
* Esvaziar o reservatório.
* Abrir nova partição de saída e voltar ao passo 2.



---

### Comparação dos Processos de Geração

* **Classificação Interna:** Gera as menores partições, o que implica em mais arquivos a intercalar.
* **Processos de Seleção:** Geram partições maiores, reduzindo o tempo total de processamento.
* **Seleção Natural:** Sofre o ônus adicional de utilizar mais operações de entrada e saída (devido ao reservatório estar em memória secundária).

## 4. Intercalação de Partições Ordenadas

### Objetivo e Problema

* **Objetivo:** Transformar um conjunto de $R$ partições classificadas em um único arquivo contendo todos os registros ordenados.
* **Problema:** Como gerar o arquivo final de forma eficiente a partir das $R$ partições?

### Algoritmo Básico de Intercalação

* De cada um dos arquivos a intercalar, basta ter em memória **um registro**.
* Considera-se cada arquivo como uma pilha (topo da pilha = registro em memória).
* **Processo:**
1. Em cada iteração, o topo da pilha com **menor chave** é gravado no arquivo de saída.
2. Ele é substituído pelo seu sucessor (leitura do próximo registro daquela partição).
3. Pilhas vazias recebem um valor sentinela (*high value*).
4. O algoritmo termina quando todos os topos forem *high value*.



### Otimização: Árvore Binária de Vencedores

Se a quantidade de arquivos a intercalar for muito grande, encontrar o menor valor de chave em cada iteração ($O(n)$) torna-se custoso.

**Funcionamento da Árvore:**

* **Nós folha:** Representam as chaves que estão nos topos das pilhas dos arquivos.
* **Nós internos:** Representam o **vencedor** (menor chave) entre seus dois filhos.
* **Raiz:** Representa o menor nó global da árvore.
* **Complexidade:** * Montagem da árvore: $O(n)$.
* A cada iteração (substituição da raiz): $\log n$ comparações.

## 5. Problemas e Soluções na Intercalação

### Desafios Reais

Seria ideal intercalar todas as partições de uma só vez, mas existem limitações físicas e lógicas:

1. O número de arquivos a intercalar pode gerar uma **Árvore de Vencedores maior do que a capacidade da memória**.
2. **Limites do Sistema Operacional:** Sistemas (como o Linux) estabelecem um número máximo de arquivos abertos simultaneamente, que pode ser menor que o número de partições.

### Intercalação Ótima

Para contornar esses limites, a intercalação exige uma série de fases, lendo de um conjunto e gravando em outro.

**Algoritmo:**

1. Determinar o número de arquivos $F$ que o algoritmo manipulará.
* $F - 1$ arquivos usados para **leitura** (entrada).
* 1 arquivo usado para **escrita** (saída).


2. Durante cada fase, $F - 1$ partições são intercaladas e gravadas no arquivo de saída.
3. As partições originais são removidas da lista e a nova partição gerada é agregada ao conjunto.
4. O processo termina quando o conjunto tiver apenas **uma partição**.

### Medida de Eficiência

Uma medida de eficiência do estágio de intercalação é dada pelo **número de passos sobre os dados**:


$$\text{Número de passos} = \frac{\text{No. total de registros lidos}}{\text{No. total de registros no arquivo classificado}}$$

* **Exemplo (F=4, 20 partições):** No exemplo citado, o total de leituras foi 6300 para um arquivo de 2000 registros, resultando em **3,15 passos**.

---

### Implementação Prática

* Criar uma lista com os nomes dos arquivos a intercalar.
* **Enquanto** houver mais de 1 arquivo na lista:
* Retirar os $F - 1$ primeiros itens da lista e intercalá-los.
* Colocar o arquivo resultante no final da lista.


* O arquivo que sobrar na lista será o arquivo resultante completo.

**Exemplo Visual (F = 4 e 10 partições):**

1. Retira $P1, P2, P3$ $\rightarrow$ Gera $P11$ (300 reg). Lista: $P4...P10, P11$.
2. Retira $P4, P5, P6$ $\rightarrow$ Gera $P12$ (300 reg). Lista: $P7...P11, P12$.
3. Retira $P7, P8, P9$ $\rightarrow$ Gera $P13$ (300 reg). Lista: $P10, P11, P12, P13$.
4. Retira $P10, P11, P12$ $\rightarrow$ Gera $P14$ (700 reg). Lista: $P13, P14$.
5. Retira $P13, P14$ $\rightarrow$ Gera $P15$ (1000 reg).
6. **Dica:** Renomear $P15$ para o nome final desejado.
