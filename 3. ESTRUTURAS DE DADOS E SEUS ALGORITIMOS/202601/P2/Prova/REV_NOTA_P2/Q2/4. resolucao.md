void busca_nivel_aux(TARVB *a, int nivel_alvo, int andar_atual, int **vet, int *tam_vet) {
    if (!a) return; // Se o nó é nulo, encerra a busca nesta ramificação.

    // Pilar da Anatomia: Chegamos no nível desejado?
    if (andar_atual == nivel_alvo) {
        int inicio = *tam_vet; 
        *tam_vet += a->nchaves; // Expandimos o tamanho total necessário
        
        // Pilar da Simetria: Realocação dinâmica para acomodar as novas chaves
        *vet = (int *) realloc(*vet, (*tam_vet) * sizeof(int));
        
        // Copia as chaves do nó atual para o vetor
        for (int i = 0; i < a->nchaves; i++) {
            (*vet)[inicio + i] = a->chave[i];
        }
    } 
    // Se ainda não chegamos no nível e o nó não é folha, precisamos descer mais
    else if (andar_atual < nivel_alvo && !a->folha) {
        for (int i = 0; i <= a->nchaves; i++) {
            busca_nivel_aux(a->filho[i], nivel_alvo, andar_atual + 1, vet, tam_vet);
        }
    }
}

# 1. Descomplicando o Problema

O enunciado pede uma função que visite uma Árvore B e "capture" todas as chaves que moram em um andar (nível) específico da árvore.
Imagine que a Árvore B é um prédio corporativo:

* A **raiz** é a cobertura (nível 0).
* Os **filhos da raiz** são o andar de baixo (nível 1).
* As **folhas** são o térreo (último nível).

**O objetivo final:** Você precisa pegar o elevador, descer até o andar `ind`, entrar em todas as salas desse andar, pegar os crachás (chaves) de todo mundo que está lá, guardar em uma caixa (um vetor alocado dinamicamente), anotar na prancheta do chefe quantas pessoas você achou (`tam_vet`) e entregar essa caixa no final.

# 2. Caixa de Ferramentas Teóricas

Para resolver isso sem mágica (aplicando nosso Pilar da Justificação de Ajuste), precisamos de três ferramentas:

1. **Busca em Profundidade (DFS - Depth-First Search):** Como a estrutura fornecida no `Material de Apoio` é baseada em ponteiros de nós para filhos, a forma mais fácil de passear pela árvore é usando recursão. Descemos nos filhos incrementando um "contador de passos" (`andar_atual`).
2. **Propriedade da Árvore B:** Lembre-se do seu material: todo nó com `N` chaves tem `N + 1` filhos. É por isso que, na hora de descer para o próximo nível, nosso laço vai de `0` até `<= a->nchaves`.
3. **Ponteiro de Ponteiro (`int vet`):** Como não sabemos de antemão quantas chaves existem no nível alvo, o vetor precisa crescer dinamicamente. Se passarmos apenas um ponteiro simples para a função auxiliar e usarmos `realloc`, a função principal não saberá o novo endereço de memória se o `realloc` mover o vetor. Passamos o endereço do ponteiro (``) para garantir a **Rastreabilidade**.

# 3. O Passo a Passo da Resolução (O Coração do Estudo)

Vamos rastrear a lógica da `busca_nivel_aux` aplicando o **Pilar da Anatomia do Passo Intermediário**. Não pulemos nenhuma etapa do pensamento.

### Bloco 1: A Condição de Parada (O Elevador quebrou?)

```c
if (!a) return;

```

* **Por que está aí?** Previne o famigerado *Segmentation Fault*. Se a árvore estiver vazia, ou se descermos até um filho que não existe (NULL), a função simplesmente aborta aquela ramificação.

### Bloco 2: Chegamos no Andar Certo? (A Coleta)

```c
if (andar_atual == nivel_alvo) {
    int inicio = *tam_vet; 
    *tam_vet += a->nchaves;
    *vet = (int *) realloc(*vet, (*tam_vet) * sizeof(int));
    for (int i = 0; i < a->nchaves; i++) {
        (*vet)[inicio + i] = a->chave[i];
    }
}

```

* **Engenharia Reversa:** O elevador abriu a porta (`andar_atual == nivel_alvo`). O que fazemos?
1. Salvamos quantos itens já temos na caixa (`inicio = *tam_vet`).
2. Atualizamos o tamanho da caixa somando a quantidade de itens que achamos nesta sala (`*tam_vet += a->nchaves`).
3. **Pilar da Simetria:** Usamos `realloc` para pedir ao Sistema Operacional: *"Por favor, estique nosso vetor para caber esse novo total"*.
4. Copiamos as chaves, colocando-as a partir do índice `inicio` até preencher as novas vagas.



### Bloco 3: Ainda não chegamos? (Continuar descendo)

```c
else if (andar_atual < nivel_alvo && !a->folha) {
    for (int i = 0; i <= a->nchaves; i++) {
        busca_nivel_aux(a->filho[i], nivel_alvo, andar_atual + 1, vet, tam_vet);
    }
}

```

* **Engenharia Reversa:** Se o nosso nível atual ainda é menor que o nível que queremos chegar (`andar_atual < nivel_alvo`), e o chão não acabou (`!a->folha`), pegamos a escada para baixo.
* **Justificação de Ajuste:** O `for` vai de `0` até `<= a->nchaves` porque, se há 2 chaves no nó, existem 3 caminhos (filhos) possíveis para descer. Chamamos a recursão passando `andar_atual + 1`. Isso é vital para a **Rastreabilidade** de onde estamos na árvore.

# 4. O Pulo do Gato (Dicas do Professor)

Aqui estão as "pegadinhas" onde a maioria dos alunos tropeça nesse tipo de exercício de laboratório:

* **A armadilha do `sizeof(int)` no `malloc/realloc`:**
Muitos alunos escrevem `realloc(*vet, *tam_vet)`. Isso quebra o código silenciosamente! Você deve multiplicar o número de elementos pelo tamanho do dado (`sizeof(int)`). Se você pedir apenas 5 "bytes" em vez de 5 "inteiros" (que dão 20 bytes), o C vai deixar você escrever por cima de memórias indevidas e corromper seu programa.
* **O Mistério do `&resp`:**
Na função principal, temos `int *resp = NULL;` e passamos `&resp` para a auxiliar. Por quê? Porque quando o `realloc` precisa de um bloco maior de memória e não encontra espaço vizinho, ele move todo o vetor para outro lugar da RAM. Se não passarmos por referência dupla (`int `), o `main` continuará apontando para a memória velha que foi deletada (Dangling Pointer).
* **Teste de Mesa Mental para Provas:**
Sempre que pedirem algo que envolva "níveis" ou "andares" de uma árvore em uma prova (seja ela Binária, AVL ou Árvore B), crie mentalmente a assinatura de uma **função auxiliar que receba um `int andar_atual**`.
